# Music Structure Lab

macOS 向けの音楽解析・作曲支援アプリケーションです。音源を読み込み、解析し、結果を編集・保存・出力できる実用的なアプリを目指しています。

解析は信号処理による推定なので、間違えることがあります。結果はすべて手で直せるようにしています。

### 音源の読み込み

- 対応形式: WAV / AIFF / CAF / MP3 / AAC (M4A) / Apple Lossless / FLAC など、macOS の Core Audio が読める形式
- 開き方: 「開く…」ボタン、メニューの ファイル > 開く… (⌘O)、ウィンドウへのドラッグ&ドロップ、Finder の「このアプリケーションで開く」
- 読み込みはバックグラウンドで行い、進捗表示と中止ができます。別のファイルを開くと前の読み込みは中止されます。
- デコードしたサンプルは 32bit float でチャンネルごとに保持し、全チャンネル平均 (モノラル) も作ります。解析はこのモノラルのデータを入力にします。
- 読み込みが終わると自動で解析します。

### 再生

- AVAudioEngine で、デコード済みのサンプルをそのまま再生します。再生位置はサンプル単位で取得し、波形上の再生位置 (オレンジの線) が追従します。
- 再生位置が表示範囲の外に出ると、自動でページ送りします。
- 3 チャンネル以上の音源は、モノラルミックスで再生します。
- 出力デバイスが変わった時は、その位置で一時停止します。

### 解析

| 項目 | 方法 |
| --- | --- |
| テンポ | スペクトルフラックス (立ち上がりの強さ) の自己相関。120 BPM を中心にした事前分布で、倍・半分のテンポの取り違えを減らしています |
| 拍 | 動的計画法による拍の追跡 (Ellis, 2007) |
| 小節頭 | 各位相について、拍の立ち上がりと和音の変化の大きさを比べて選びます (拍子は既定で 4/4、変更可) |
| キー | 曲全体のクロマ (12 音名の強さ) と Krumhansl-Schmuckler のプロファイルの相関 |
| コード | 拍ごとのクロマと 24 種の三和音のテンプレートの一致度を、ビタビ法で平滑化。無音はノーコード (N.C.) |
| 構造 | 拍ごとの特徴 (クロマ + 音色) の自己類似行列に、チェッカーボード・カーネル (Foote, 2000) をかけて境界を探し、小節頭に寄せます。時間をそろえて似ている区間に同じ記号 (A, B, C…) を付けます |

FFT は Apple プラットフォームでは Accelerate (vDSP) を使います。解析は 22.05kHz 付近に間引いた信号で行います。

### 編集 (インスペクタ)

- **全体**: テンポ (×2 / ÷2)、拍子、小節頭の位置 (1 拍ずつ)、拍の位置の微調整 (±10ms)、キー、移調 (半音ずつ)
- **セクション**: 名前 (候補から選択可、同じ記号のセクションに一括適用)、記号、カーソル位置で分割、次と結合、削除、境界のドラッグ、境界を小節頭に揃える
- **コード**: ルート・種類 (メジャー / マイナー / dim / aug / sus4 / 7 / maj7 / m7 / N.C.)、キーのダイアトニック・コードから選択、カーソル位置で分割、次と結合
- ローマ数字 (例: C キーで Am → vi) とノンダイアトニックの表示
- **構成**: セクション一覧。**コード譜**: 小節ごとのコード譜 (コピー・書き出し可)。**メモ**: プロジェクトに保存される自由記述
- すべての編集は ⌘Z / ⇧⌘Z で取り消し / やり直しできます

### 保存と書き出し

- **プロジェクト (.mslab)**: 音源への参照 (サンドボックス用のブックマーク、絶対パス、相対パス) と解析結果・編集・メモを JSON で保存します。音源そのものは含みません。開く時に音源が見つからなければ、場所を尋ねます。音源の長さが保存時と違う場合は、保存された解析結果を使わずに解析し直します。
- 未保存の変更がある状態で別のファイルを開く・閉じる・終了する時は、保存するか確認します。
- **書き出し** (ファイル > 書き出し、またはツールバー):
  - 解析結果 (JSON)
  - 表形式 (CSV): セクション・コード・拍を 1 行ずつ
  - MIDI: 拍ごとのテンポマップ、拍子、調号、セクション名のマーカー、コードの構成音とコード名。DAW に読み込むと拍・小節線が音源とそろいます
  - Audacity のラベル (セクション)
  - コード譜 (テキスト)
  - 選択範囲 (セクション・コード区間) の音声 (WAV 24bit)

### パート分離と個別再生

ツールバーの「パート分離」、メニューの 解析 > パートを分離 (⌥⌘P)、またはインスペクタの「パート」タブから実行します。曲を ドラム・ベース・コード(伴奏)・ボーカル・メロディ の 5 つに分け、パートごとの音量・ミュート (M)・ソロ (S)・「このパートだけを聴く」で別々に再生できます。波形表示を「パート別」にすると、パートごとの波形を並べて表示します。5 つのパートは WAV で書き出せます。

分離の方法は 2 つあり、画面に常にどちらで分離したかを表示します。

| 方法 | 内容 |
| --- | --- |
| 近似分離 (信号処理、標準) | STFT の振幅にメディアンフィルタをかけて打楽器成分と持続音成分に分け (HPSS)、打楽器成分をドラム、持続音成分の低域 (180〜300Hz 以下) をベース、ステレオで左右に共通する (中央に定位した) 成分をボーカル、主旋律の音高を追って (倍音の重み付き和 + 跳躍を抑える動的計画法) その倍音をメロディ、残りをコード(伴奏) にします。全パートの和は元の音と一致します。**パート間の漏れが大きい簡易的な方法で、楽器ごとの本当の分離ではありません。** ボーカルには中央に置かれた楽器も入ります。モノラル (左右が同じ) の音源ではボーカルを分けられず、ボーカルは無音になります (画面に理由を表示)。 |
| 機械学習モデル | 利用者が用意した Core ML モデル (Demucs 系) で分離します。モデルは同梱していません。`drums`→ドラム、`bass`→ベース、`vocals`→ボーカル、それ以外→コード(伴奏)。モデルはメロディを出力しないので、伴奏系の音源 (other、htdemucs_6s ならギター・ピアノも) ごとに旋律を推定し、場面ごとに旋律が最もはっきりした音源から音高追跡で取り出します。メロディとコードの分離には htdemucs_6s をおすすめします。モデルの形式と、Demucs からの変換スクリプト (変換は Linux で確認済み、Core ML での推論は macOS で未確認) は [docs/STEM_MODEL.md](docs/STEM_MODEL.md) を参照。モデルが無い時は近似分離になります。 |

- 分離はバックグラウンドで行い、進捗表示と中止ができます。分離中も再生できます。
- 分離したパートはメモリ上に持ちます (ステレオ 4 分の曲で約 430MB)。プロジェクトには保存しないので、開き直した時は分離し直します。
- パートは別々の AVAudioPlayerNode で同じ時刻から鳴らすので、ずれません。音量・ミュート・ソロは再生中にすぐ反映されます。クリック音はパートのミュートの影響を受けません。

### 波形表示

- 多段解像度のピーク (min/max) を読み込み時に作るので、長い曲でも全体表示・拡大表示が軽く動きます。
- 1 画素に 1 サンプル未満まで拡大すると、個々のサンプルを結ぶ線 (さらに拡大すると点) で表示します。

| 操作 | 動作 |
| --- | --- |
| クリック | 再生位置を移動 (再生中はその位置から再生を続ける) |
| スペース | 再生 / 一時停止 (テキスト入力中を除く) |
| セクション帯・コード帯のクリック | 選択して、その先頭へ移動 |
| セクション帯の境界のドラッグ | 境界を動かす |
| ⌘L | 選択範囲をループ再生 |
| ⌥⌘C | クリック音 (小節頭は高い音) |
| ⌘R | 解析 / 解析し直す |
| ⌘K / ⌥⌘K | カーソル位置でセクション / コードを分割 |
| ⌘J | 選択を次と結合 |
| ⌥⌘P | パートを分離 |
| ⌘S / ⇧⌘S | 保存 / 別名で保存 |
| ドラッグ / 横スクロール / マウスホイール | 左右に移動 |
| ⌘ または ⌥ + スクロール、ピンチ | ポインタ位置を中心に拡大・縮小 |
| ⌘+ / ⌘- / ⌘0 | 拡大 / 縮小 / 全体表示 |
| 下部ミニマップのクリック・ドラッグ | その位置へ移動 |

## ビルドと起動

必要環境: macOS 13 以降、Xcode 15 以降 (Swift 5.9 以降)

### Swift Package として (いちばん手軽)

```sh
swift run MusicStructureLab   # アプリを起動
swift test                    # テストを実行
```

Xcode で `Package.swift` を開き、`MusicStructureLab` スキームを実行することもできます。

### .app バンドルとして (サンドボックス付き)

[XcodeGen](https://github.com/yonaskolb/XcodeGen) で Xcode プロジェクトを生成します。

```sh
brew install xcodegen
xcodegen generate
open MusicStructureLab.xcodeproj
```

署名は Xcode の Signing & Capabilities で自分のチームを選んでください。

## プロジェクト構成

```
Sources/
  MSLCore/            プラットフォーム非依存のモデルと解析ロジック
    Analysis/         解析 (MusicAnalyzer, Rhythm, Harmony, Structure, Features, DSP/FFT・Spectrogram)、
                      解析結果のモデルと編集操作 (AnalysisModels, AnalysisEditing)、音楽理論 (MusicTheory)
    Separation/       パート分離 (SpectralStemSeparator, RealFFT)、パートとミキサーのモデル (Stems)
    Export/           書き出し (MIDIExporter, AnalysisExporters)
    Project/          プロジェクトファイル (ProjectDocument)
    Audio/            DecodedAudio, AudioFileInfo
    Waveform/         多段解像度の波形ピーク (WaveformBuilder / WaveformOverview)
    Timeline/         表示範囲の計算 (WaveformViewport)、時間の書式
  MSLAudio/           AVFoundation による音源デコード (AudioFileLoader)、再生 (AudioPlayer、パート別の同時再生)、
                      WAV 書き出し (AudioExporter)、Core ML モデルでのパート分離 (MLStemSeparator)
  MusicStructureLab/  SwiftUI アプリ本体
    Models/           AudioDocumentModel (読み込み・再生・解析・編集・保存の状態)
    Views/            画面 (ContentView, WaveformPanel, AnalysisLanes, InspectorView, StemMixerView, 描画ビュー)
Tests/
  MSLCoreTests/       波形ピーク・表示範囲・時間書式・解析 (合成音源)・編集・書き出し・プロジェクト・パート分離 (合成音源) のテスト
  MSLAudioTests/      実際に WAV を書き出して読み込むテスト、再生バッファのテスト
tools/                Demucs を Core ML に変換するスクリプト
project.yml           XcodeGen 用の .app 定義
```

解析ロジックは UI や AVFoundation から切り離してあるので、単体テストできます。
