# 実機での確認項目

自動テスト (GitHub Actions の macOS 環境での `swift build` / `swift test` と .app のビルド) では確かめられない、
実際に操作・試聴して確認が必要な項目です。`swift run MusicStructureLab` で起動して確認してください。

確認済みの項目: 音源の読み込みと波形表示、再生 (S さんが確認済み)。

## 1. 解析

- [ ] 音源を開くと自動で解析が始まり、進捗 (段階名と %) が表示される。「中止」で止まる
- [ ] 3〜5 分の曲で、解析にかかる時間が許容範囲か (`swift run` はデバッグビルドなので遅め。`swift run -c release MusicStructureLab` でも比較)
- [ ] テンポ (BPM) が実際の曲とおおむね合っている。倍・半分になっていたら「×2」「÷2」で直せる
- [ ] 拍の線が実際の拍とそろっている (⌥⌘C のクリック音を鳴らして聞き比べる)。ずれていれば「拍の位置 ±10ms」で直せる
- [ ] 小節の頭 (濃い線と小節番号) が正しい。ずれていれば「小節頭 ◀ ▶」で直せる
- [ ] キーがおおむね合っている (平行調、例えば C major と A minor の取り違えはありうる)
- [ ] コードがおおむね合っている (認識するのはメジャー / マイナーの三和音のみ。7th などは手で直す)
- [ ] セクションの区切りと記号 (同じ繰り返しに同じ記号) が妥当か。曲によっては細かすぎる・粗すぎることがある

## 2. 表示と操作

- [ ] 波形の上にセクション帯 (色付き) とコード帯が表示され、拡大・スクロールに追従する
- [ ] 拍線・小節線・小節番号が、拡大率に応じて間引かれて表示される
- [ ] セクション帯・コード帯をクリックすると選択され、インスペクタに編集欄が出て、その先頭に再生位置が移る
- [ ] セクションの境界にポインタを合わせると左右矢印のカーソルになり、ドラッグで境界を動かせる
- [ ] スペースで再生 / 一時停止できる。インスペクタの名前欄に文字を入力している時はスペースが文字として入る
- [ ] ループ (⌘L / ツールバーの ↻) をオンにすると、選択中のセクション・コード区間を繰り返し再生する
- [ ] クリック音 (⌥⌘C / メトロノームのボタン) が拍に合わせて鳴り、小節頭は高い音になる
- [ ] インスペクタの表示 / 非表示 (ツールバー右端) が切り替わる

## 3. 編集

- [ ] テンポ・拍子・小節頭・キー・移調の変更が、帯・拍線・コード名に反映される
- [ ] セクションの名前 (候補メニュー、「同じ記号すべてに適用」)、記号の変更
- [ ] カーソル位置で分割 (⌘K / ⌥⌘K)、次と結合 (⌘J)、セクションの削除
- [ ] コードのルート・種類の変更、ダイアトニック・コードのボタン、N.C.
- [ ] 編集 > 取り消す (⌘Z) / やり直す (⇧⌘Z) で、どの編集も戻せる (メニューに「名前を変更を取り消す」などと表示される)
- [ ] 「構成」タブのセクション一覧、「コード譜」タブ (コピー)、「メモ」タブの入力

## 4. 保存と読み込み

- [ ] ⌘S でプロジェクト (.mslab) を保存できる。タイトルの「— 編集済み」が消える
- [ ] アプリを終了して起動し直し、.mslab を開く (⌘O またはドラッグ&ドロップ) と、音源と編集した解析結果・メモが復元される (解析し直さない)
- [ ] 音源ファイルを移動してから .mslab を開くと、音源の場所を尋ねられ、指定すると開ける
- [ ] 編集後に別のファイルを開く・閉じる (⇧⌘W)・終了 (⌘Q) すると、保存するか確認される
- [ ] 最近使った項目 (ファイル > 最近使った項目を開く) に .mslab が入る

## 5. 書き出し

- [ ] JSON / CSV がテキストエディタや表計算ソフトで開ける (CSV は UTF-8。Excel で文字化けする場合は「データ > テキストから」で読み込む)
- [ ] MIDI を DAW (GarageBand / Logic など) に読み込むと、テンポマップで小節線が音源とそろい、セクション名がマーカーとして入り、コードのトラックがある
- [ ] Audacity のラベルが「ファイル > 取り込み > ラベル」で読める
- [ ] コード譜 (テキスト) の内容
- [ ] 選択範囲の音声 (WAV) が書き出せて、正しい範囲が再生される

## 6. パート分離と個別再生

近似分離 (モデル不要):

- [ ] ツールバーの「パート分離」で分離でき、進捗が出て、中止できる。4 分程度の曲で何秒かかるか (Release / Debug とも。Debug でも MSLCore は最適化している)
- [ ] 分離後、波形表示が「パート別」になり、ドラム / ベース / コード(伴奏) / ボーカル / メロディ の 5 段が出る
- [ ] 歌のある曲で、ボーカルだけを聴いた時にどの程度声が取れているか (近似分離は中央定位を使うので、中央の楽器も混ざる)。メロディ・コードに声がどれだけ残るか
- [ ] モノラル音源 (または左右が同じ音源) では、ボーカルが無音になり、ボーカルの行に理由が表示される
- [ ] インスペクタ「パート」で、M (ミュート)・S (ソロ)・ヘッドホン (このパートだけ)・音量スライダーが再生中にすぐ効く。ミュートしたパートの波形が薄くなる
- [ ] 全パートを鳴らした時、元の音源と聴き比べて差が無い (「パート別に再生」のオン/オフで比べる)
- [ ] パート別再生中に、シーク・ループ・クリック音・ループ範囲の変更がこれまでどおり動く。パート同士がずれない
- [ ] 実際の曲で、ドラムだけ・ベースだけ・メロディだけを聴いた時の分離の程度 (近似なので漏れは大きい。どの程度使えるかを確認)
- [ ] メモリ使用量 (アクティビティモニタ) が極端に増えない。長い曲 (10 分程度) でも分離できる
- [ ] 分離したパートを「WAV で書き出す…」でフォルダに書き出せる (曲名-drums.wav など 5 つ。ボーカルは曲名-vocals.wav)
- [ ] 別の音源を開く・閉じると、パートが消えて元の音源の再生に戻る
- [ ] モノラル・5.1ch など 2ch 以外の音源でも分離・再生できる

機械学習モデル (任意):

- [ ] `tools/convert_demucs_to_coreml.py` で HTDemucs を変換でき、最後に表示される「Core ML と PyTorch の出力の差」が出力の最大値に比べて十分小さい (失敗した場合はエラー内容を共有してほしい)
- [x] 変換スクリプトで HTDemucs を変換できた(macOS で確認済み。CPU のみ一致、CPU+GPU / Neural Engine はずれるので cpuOnly を記録)
- [ ] CPU のみで分離した時にかかる時間(4 分程度の曲で)
- [ ] 変換したモデルを「モデルを読み込む…」で読み込める。モデル名・サンプルレート・区切りの長さ・パート名が表示される
- [ ] 機械学習モデルで分離した結果の品質、かかる時間、44.1kHz 以外の音源 (48kHz など) での動作
- [ ] 機械学習モデルでは、モデルの vocals がボーカルに入り、メロディは伴奏から音高追跡で取り出される (ミキサーの「分離方法」の表示にもそう出る)
- [ ] アプリを再起動してもモデルが残っている。「削除」で消せる
- [ ] モデルが無い状態で「機械学習モデル」を選ぶと、近似分離になることが画面に表示される

## 7. .app としてビルドした場合 (XcodeGen)

`xcodegen generate` → Xcode で署名チームを設定して実行。

- [ ] サンドボックス下で、音源・プロジェクトを開ける、保存・書き出しできる
- [ ] 保存したプロジェクトを、アプリを再起動してから開いても音源にアクセスできる (セキュリティスコープ付きブックマーク)
- [ ] Finder で .mslab をダブルクリックするとこのアプリで開く
